An archive workbench for the local collection

Frame View shows the archive. This app works on it. It scans a root and reports what's there. It finds duplicates, silent videos and files in the wrong format. It plans conversions to the archive formats Gather Box already writes: AVIF at quality 70 and speed 6, and MP4 for GIFs. Every change is a plan you review first, and nothing is hard-deleted.

Working name throughout: Glazier. Alternatives are in §2; everything renames cleanly before Phase 1.

03 · Safety model

Rules every feature follows

The local archive is the source of truth (CLAUDE.md, docs/ARCHITECTURE.md). Every other app only reads it or adds to it; this one moves, renames and replaces files in bulk. So these rules come before any feature.

  1. Scanning is read-only. The catalog lives in the app's user-data folder. Nothing is written inside a root until you apply a plan.
  2. Every change is a plan first. Each action builds a plan that says what moves where, how many bytes change and what Lockstep will see. It runs only when you press Apply, the same split as lockstep plan and push.
  3. Nothing is hard-deleted. Removed files and replaced originals go to .latch-works-holding/ in their own root, which every scanner skips. Undo is a rename back. Empty holding sends the contents to the macOS Trash.
  4. Re-check before touching. Just before each step the executor stats the file again. If size, mtime or ctime changed since the scan, it skips the file and says why. hashFileContents in media-index applies the same rule.
  5. Conversions are atomic and keep their dates. Write to a temp file beside the source, verify it, copy the mtime, rename it into place, then move the original to holding. Frame View and Pane View sort by mtimeMs, so a converted file keeps its place in date order.
  6. Stay inside the root. Don't follow symlinks and don't touch non-regular files. The repo already rejected both for its scanners, on the same safety grounds.
  7. Everything applied is journaled. Every applied step is recorded with before/after paths and sizes, and undo works from that record. docs/runbooks/glazier.md documents each mutating action, as CLAUDE.md requires.

05 · Features

What each part does

Inventory · Phase 1

Know what's there

  • Reads kind, extension, real format (magic bytes), dimensions, animation, alpha, bit depth, colour profile, video and audio codecs, duration, bitrate.
  • Reports totals by kind, extension, codec and folder, plus the largest folders.
  • Findings: extension mismatch, zero-byte, undecodable, system junk (media-domain's list), empty folders, unsupported types (HEIC and PSD aren't in any app's extension list today), MKV and BMP originals that Pane serves by presigned URL.
  • Fixes: rename to the real extension (Gather Box's rename-avif/rename-mp4 rule), clean junk, remove empty folders.
Duplicates · Phases 2 and 5

Find copies, keep one

  • Exact: group by size, hash the first and last 64 KB of same-size files, then full SHA-256 only for what still collides. Most files are never fully read.
  • That SHA-256 is Lockstep's source ID, so exact duplicates already share one object in Pane's bucket. They cost local disk and extra library entries, not S3.
  • Hard links (same device and inode) show as one file with two names; removing one frees nothing.
  • Near (P5): a 64-bit dHash per still catches resized copies and PNG/AVIF twins. For videos, dHashes of five frames plus duration catch a GIF beside its MP4, and re-encodes.
  • Keeper rules, in order: protected folders, archive format, more pixels, oldest mtime, shortest path, then natural name order.
Sound · Phases 1 and 4

Which videos have sound

  • States: No audio track · Silent track · Has sound · Not analyzed yet.
  • Track presence comes from ffprobe's stream list. Frame View already runs ffprobe but only reads the video stream.
  • Silence needs a pass: ffmpeg volumedetect over the track. A max volume below about −60 dBFS counts as silent (calibrate in Phase 0). It decodes the whole track, so it runs on demand or in the background and is cached.
  • Actions: filter and sort; strip a silent track by stream copy, with no re-encode, keeping the mtime.
Manage · Phase 1

Day-to-day file work

  • Table and grid, facet filters, saved views ("PNG over 5 MB", "no sound").
  • Multi-select: move to holding, move to folder, batch rename with a preview, fix extension.
  • Reveal in Finder, open with the default app, and Quick Look via BrowserWindow.previewFile.
  • Holding view with restore, and a journal with undo for every applied step.
  • Later: Open in Frame View, once Frame View accepts a path to open.
06 · Optimize in detail

One format policy for the whole archive

Gather Box already decides what the archive stores, in archive-media-policy.ts and avif-codec.ts. Glazier must apply exactly the same policy to files that are already on disk. If it's copied, the two copies drift. So Phase 3 starts by moving the policy into a new shared package, packages/media-format, which both apps import.

SourceTargetSettings (from Gather Box today)
PNG, JPEG, WebP, BMP stillsAVIFquality 70, speed 6, 8-bit, alpha at the same quality. Retries at speed 8 when the wasm encoder runs out of memory (hard-edged art from about 30 MP). Above about 64 MP no speed fits.
GIFMP4Gather Box uses mediabunny: H.264, quality "high", a keyframe every 2 s, alpha discarded. Node has no WebCodecs, so Glazier uses ffmpeg with settings matched to that output in Phase 0.
AVIF or MP4 bytes with another extensionrenameNo re-encode (rename-avif, rename-mp4).
Videos, PDFs, AVIFunchangedThe policy leaves them alone. MKV/MOV → MP4 remux is a separate, lossless action (Phase 4).

Which AVIF encoder (decision D3)

Recommended

A · Gather Box's encoder, in Node

Run the same libavif wasm build (@jsquash/avif) in worker threads with the same options. Its codec call already takes the wasm binary as an argument, so only the loader changes. The output then matches whichever tool wrote the file.

Cost: one encode per worker, the 2 GiB wasm heap ceiling, and the speed 8 fallback come along with it.

Alternative

B · sharp's native AVIF

libheif with aom: multithreaded, faster, no heap ceiling, and already a Frame View dependency.

Cost: sharp takes effort 0–9 instead of speed, and its quality scale differs, so q70/s6 has no exact equivalent. Matching needs calibration and can drift. Possibly useful as a fallback for images over 64 MP.

Phase 0 settles it: encode about 20 representative files both ways (photo, line art, transparent PNG, a phone photo, a P3 PNG, one over 30 MP) and compare size, SSIM and wall time.

Decode correctly first

Gather Box decodes with createImageBitmap(blob, { imageOrientation: "from-image" }), which applies EXIF rotation and converts to 8-bit sRGB. Glazier does the same with sharp: rotate, convert to sRGB, 8-bit RGBA. Without that, phone photos come out sideways and wide-gamut PNGs shift colour.

Edge cases

  • Animated WebP and APNG are detected (sharp reports more than one page). They go to MP4 or are skipped with a reason, never flattened. Side finding: Gather Box sends every WebP to the still encoder, and createImageBitmap keeps only the first frame, so an animated WebP collected today loses its animation. Fixing that in media-format fixes both apps.
  • The AVIF isn't smaller. If the output isn't at least 5% smaller (tunable), keep the source and record why. Tiny pixel art can lose.
  • Very large images (over about 64 MP) are skipped with a reason, unless option B is enabled as a fallback.
  • Metadata. EXIF is dropped after orientation is applied, matching Gather Box's output. Finder tags (extended attributes) are copied across.
  • Gather Box sidecars aren't written yet. Once a folder has .latch-works.source.json, a conversion rewrites the matching files[].path entry.

Per-file sequence

1  re-stat the source; skip it if it changed
2  decode (rotate, sRGB, 8-bit) and encode
3  write <name>.glazier-tmp beside the source
4  verify: it decodes, same width and height
   (frame count and duration for MP4), smaller
5  copy the mtime and Finder tags
6  rename into place
7  move the original to .latch-works-holding/
8  journal the step

Leftover *.glazier-tmp files are removed on startup, so quitting mid-run is safe. The queue uses N−1 worker threads, can pause, and has a low-priority mode so the Mac stays usable. The estimate encodes a sample stratified by format and size and reports a range.

07 · Scan passes

Cheap first, expensive on demand

Each pass caches its result against the file's fingerprint (size, mtime, ctime) and a pass version. A changed file re-runs only the passes it needs; changing an algorithm bumps its version.

PassReadsProducesWhen
WalkDirectory entries, lstatPath, size, mtime, ctime, device and inode, extensionEvery scan
SniffFirst 4 KBReal format, extension mismatch, zero-byteNew or changed files
ProbeHeaders via sharp or ffprobeDimensions, pages, alpha, bit depth, colour space, codecs, duration, bitrate, audio streams, decode errorsNew or changed files
HashSame-size files only: 64 KB head and tail, then fullSHA-256 (Lockstep's source ID)Opening Duplicates, or when idle
FingerprintDecoded 9×8 grey image; five video framesdHash, video signatureOpt-in (Phase 5)
LoudnessDecoded audioMax and mean dB → silent or soundOpt-in (Phase 4)

Finding near-duplicates without comparing every pair: split each 64-bit dHash into eight bytes and look up candidates by byte. Two hashes within Hamming distance 7 must share at least one identical byte, so this misses nothing up to that threshold.

08 · Architecture

Same shape as Lockstep and Frame View

Renderer

React 19, Tailwind 4, lucide-react, a virtualized table. Talks only through the preload bridge, with zod-validated contracts in Lockstep's ipcContracts style.

Main

Windows, menus, dialogs, Reveal in Finder, Quick Look, Trash. Starts the engine and passes a MessagePort to the renderer for paged queries.

Engine · utilityProcess

glazier-core: the SQLite catalog (node:sqlite + drizzle, WAL, as in Frame View), the pass scheduler and the plan executor. It's the only code that writes into a root.

Workers · worker threads

Walk and sniff; probe (sharp, ffprobe); hash; encode (AVIF wasm, ffmpeg). Sized to N−1 cores and pausable.

Catalog

~/Library/Application Support/Glazier/catalog.sqlite. Rebuildable from the archive at any time, so it's never the source of truth.

Archive roots

Read by every pass. Written only by the executor, and only to apply a plan.

The engine runs out of process because node:sqlite is synchronous: catalog queries and pass scheduling over tens of thousands of rows mustn't block Electron's main thread. Keeping the engine free of Electron imports also makes a CLI a thin wrapper later, as lockstep-core did for Lockstep.

11 · Roadmap

Six phases, each one shippable

Phase0

Spike and decisions S

On the real archive, measure walk, probe and hash throughput; compare AVIF options A and B; calibrate the silence threshold; match ffmpeg's GIF output to Gather Box's. Record the answers to §12 in ADR 0003, then write the Markdown summary of plan 058 and its index row.

Done when every decision in §12 has an answer and the ADR is merged.

Phase1

Foundation, inventory and manage L

Scaffold apps/glazier from Lockstep. Build glazier-core with the walk, sniff and probe passes and the catalog. Ship Overview, Library and findings; holding, journal and undo; move, rename, Reveal and Quick Look; audio-track presence; the media-domain holding rule; the runbook; the icon master; and an e2e project with pnpm e2e:glazier.

Done when a scan of the fixture root shows correct counts by kind, extension and audio track, and move-to-holding then undo round-trips in e2e.

Phase2

Exact duplicates M

Staged hashing, hard-link awareness, the group view, keeper rules and protected folders, and plan review with the Lockstep impact.

Done when the fixture's duplicate pair resolves to the rule's keeper, and its hard-link pair is labelled and left out of reclaimable bytes.

Phase3

Optimize L

PR 1 extracts media-format with Gather Box's behaviour unchanged. Then: the candidate report with sample estimates, the encoder pool, the verify/atomic/mtime sequence, animated-image detection, skip-if-not-smaller, and GIF → MP4.

Done when the fixture PNG becomes an AVIF with the policy options, keeps its mtime and lands its original in holding, and the fixture's animated WebP is skipped with a reason.

Phase4

Sound and video M

The loudness pass, Silent and Has-sound filters, strip a silent track, a codec and bitrate report, and lossless MKV/MOV → MP4 remux when every stream fits in MP4.

Done when the fixture's silent-track video and no-track video land in the right states, and a remuxed MKV plays in Frame View.

Phase5

Near-duplicates L

dHash with the byte index, cross-format twins, video signatures, and a side-by-side compare with a slider and flicker toggle.

Done when the fixture's resized copy and PNG/AVIF twin each form a group, and no unrelated fixture image joins one.

Later

After v1

The glazier CLI over glazier-core; Open in Frame View; watch mode; a Showcase docs page; Windows and Linux builds.

12 · Your call

Decisions needed

Each one has a recommended default. Only these change what gets built.

D1 · Name

GlazierFrame BenchMullionSomething else

The rest of the plan uses Glazier; a rename before Phase 1 costs nothing.

D2 · Where removed files go

Holding folder per rootmacOS Trash directly

The holding folder is a same-volume rename: instant, with exact undo. Electron's shell.trashItem doesn't report where the file went, so the app couldn't offer undo for the Trash. Whether Finder's Put Back works for items trashed that way is unverified. Space from the holding folder comes back when you empty it.

D3 · AVIF encoder

Gather Box's wasm encodersharp nativewasm, with sharp above 64 MP

Phase 0 measures both. Parity with Gather Box is the reason for the default.

D4 · The original after a verified conversion

Move to holdingTrash immediatelyKeep beside the AVIF

Keeping it beside the AVIF would make Phase 5 report every converted file as a duplicate.

D5 · GIF → MP4

In scope, Phase 3Report only

Gather Box already converts GIFs on the way in, so files collected later already match.

D6 · Re-encode videos

Report onlyOffer an AV1/HEVC action

Lossy, slow, and outside the current archive policy. Lossless remux and track stripping are in scope either way.

D7 · Platform

macOS first, code kept cross-platformAll three from day one

Finder, Quick Look and signing are macOS; Frame View shows the rest ports without trouble.
