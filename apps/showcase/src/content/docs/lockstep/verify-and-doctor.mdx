# Verify and Doctor

Use these read-only checks to catch misconfiguration before a long push and to detect drift afterward.

## Doctor (desktop and CLI)

On desktop, click **Doctor** in the command dock. On the CLI, run `doctor`. Both check the active profile environment:

- Source folder exists and is readable (when set)
- Pane View API URL and sync token are present
- Pane View responds when URL and token are both set (snapshot fetch)

Run this after creating a profile or changing tokens. Fix every failed check before planning a large push.

Typical failures:

| Issue | What to check |
| --- | --- |
| Unreachable URL | Typo, VPN, or server down |
| Unauthorized token | Expired or wrong token for this library |
| Missing source | Profile points at moved or unmounted disk |

## Verify (CLI only)

**Verify** is available on the [Lockstep CLI](/docs/lockstep/cli), not in the desktop app.

It compares your local archive to a **snapshot file** you provide with `--remote-snapshot`. The file is either a JSON array of `{ "path", "size", "sha256" }` entries (`sha256` is optional) or a saved response from Pane View's `GET /api/sync/snapshot` (authorized with the sync token), which wraps that array in `entries`. Without `--hash`, drift is path and size based; with `--hash`, content hashes are compared too.

Verify exits with a non-zero status when any path differs, so scripts can react to drift.

Use verify when:

- You want automated assurance after manual file edits
- A push was interrupted and you need a yes/no drift answer
- You script checks alongside backup routines

Verify does not fix drift, it only reports. Plan and push (or restore from backup) to reconcile. There is no “export snapshot” button in Lockstep; obtain snapshot JSON from Pane View’s sync API or a saved file from a previous run.

## Suggested order

1. **Doctor**: environment healthy?
2. **Plan**: expected diff?
3. **Push**: apply uploads and updates
4. Optional CLI **verify**: still aligned with snapshot?
