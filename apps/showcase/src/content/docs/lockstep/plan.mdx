# Lockstep plan

**Plan** walks your source folder, detects media, and compares against the remote index. It never uploads or deletes anything.

![Lockstep desktop plan results](/screenshots/lockstep/plan.png)

## Running plan

1. Select your active profile in Lockstep desktop.
2. Click **Plan** in the command dock.
3. Wait for the scan and diff to finish.
4. Review the summary counts and item list on the **Plan** tab.

The CLI `plan` command does the same comparison from a terminal. See [Lockstep CLI](/docs/lockstep/cli).

## Interpreting counts

| Count | Meaning |
| --- | --- |
| Upload | New local files not yet on the remote library |
| Update | Local file differs from remote (see hashing note below) |
| Keep | Already in sync, no action needed |
| Delete | Remote entry with no local file. Only **Prune** removes it, never Push |

Treat **keep** as reassurance; focus on upload and update before pushing.

## Deletes and Prune

The deletes you review here are the ones **Prune** applies. Prune does not plan again: it deletes those remote entries and skips any whose file is back in your source folder. If your folder or the remote library changed since this plan, run **Plan** again before pruning. See [Deletes are separate](/docs/lockstep/push#deletes-are-separate).

## Hashing note

Desktop **Plan** compares by path and size only. A content change that keeps the same file size shows as **keep** until push.

**Push** re-plans with remote-aware hashing before uploading, so update counts can grow compared with the last plan.

## When to plan without pushing

- After a Gather Box collection day
- After renaming or moving folders
- Before any push when counts look unexpectedly large
- On a schedule, as a weekly review

## Filtering the item list

The **Filter by path** box on the Plan tab narrows the list by a case-insensitive path substring. Keep items are hidden from the list. Use this to sanity-check one creator folder at a time.
