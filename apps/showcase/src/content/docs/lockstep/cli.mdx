# Lockstep CLI companion

The desktop app covers everyday sync. The CLI companion runs the same engine headlessly for automation or remote shells.

## When to use it

- Scheduled plan-only reports
- Push from a machine without opening the desktop UI
- Capped pushes with `--max-changes`
- Verify against a snapshot file
- Explicit prune of planned deletes in scripts

For most personal use, prefer the desktop app for visibility into progress and errors.

## Invoke

From the repo (with packages built and env sourced as needed):

```bash
cd apps/lockstep-cli
pnpm exec tsx src/cli.ts plan --source /path/to/archive
```

Or: `pnpm --filter @latch-works/lockstep start plan --source …`

Do not put a bare `--` between `pnpm start:lockstep` and the subcommand.

## Commands

| Command | Purpose |
| --- | --- |
| `plan` | Read-only diff summary |
| `push` | Upload and register new/changed originals (never deletes) |
| `prune` | Apply planned remote deletes (requires confirm or `--yes`) |
| `verify` | Compare tree to `--remote-snapshot` |
| `doctor` | Environment and connectivity checks |

Push and prune are separate — same split as **Push** and **Apply deletes** in the desktop app.

## Useful flags

| Flag | Used by | Purpose |
| --- | --- | --- |
| `--source` | all | Local archive root |
| `--api-url` | plan/push/prune/doctor | Pane View API base URL |
| `--hash` | plan/verify | Full content hashing (plan); hash compare (verify) |
| `--max-changes` | push/prune | Cap how many changes apply in one run |
| `--upload-concurrency` | push | Parallel uploads |
| `--remote-snapshot` | plan/verify | Snapshot JSON path (required for verify) |
| `--show-skipped` | plan | Include skipped items in output |
| `--yes` | prune (required non-interactively) | Skip prune confirmation |
| `--api-token-env` | auth | Env var name holding the sync token |

**Push always uses remote-aware hashing** when talking to Pane View. Desktop plan is size-oriented by default; CLI plan uses hashing only with `--hash`.

`--yes` gates **prune**, not push. Push runs without an interactive confirm once arguments are complete.

## Configuration

Defaults live in `~/.latch-works/lockstep.json` (source path, API URL, etc.). **Keep tokens in environment variables**, not in the config file.

## Interactive mode

Running with no arguments in a TTY starts a wizard for **plan / push / verify / doctor**. Prune is not in the wizard — run `prune` as an explicit subcommand.

## Safety

- Always plan before push in automation scripts.
- Run prune only when you intend to apply delete entries from the plan.
- Prefer `--max-changes` on first pushes to a new remote library.
- Run `doctor` before the first automated push to a new remote library.
