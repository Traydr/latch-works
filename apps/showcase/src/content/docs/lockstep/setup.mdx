# Lockstep setup

Lockstep stores one or more **profiles**. Each profile ties a local source folder to a Pane View instance and sync token.

## Create a profile

1. Open the Lockstep desktop app.
2. Choose **Create your first profile** or **Add profile**.
3. Fill in:
   - **Name** — label for this archive (e.g. "Main archive")
   - **Source folder** — root of your local archive tree
   - **Pane View API URL** — the base URL of your Pane View instance (API host, not only the browse UI)
   - **Sync API token** — secret that authorizes uploads (from your Pane View operator)

4. Save the profile.

## Sync token handling

Tokens authorize Lockstep to register uploads. They are separate from your Pane View sign-in password.

- On desktop, Lockstep encrypts saved tokens with OS key storage when available.
- If encryption is unavailable, you may enter a token for the current session only.
- Never paste tokens into public chats or screenshots.

## Active profile

Select which profile is active before running plan, push, apply deletes, or test connection. Switch profiles when you maintain more than one archive or remote library.

## Before the first push

1. Click **Test connection** on the profile to confirm source path, URL, token, and that Pane View responds.
2. Run **Plan** and read counts — an empty remote library should show many uploads and zero updates.
3. Push a small test folder first if you are unsure.

## CLI configuration

If you use the command-line companion, defaults live in `~/.latch-works/lockstep.json` while tokens stay in environment variables. See [Lockstep CLI](/docs/lockstep/cli).
